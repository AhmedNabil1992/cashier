# قائمة العمل التنفيذية — eCashier فوق ERP الحالي

**الإصدار:** 2.1 — مواءمة 14 سبتمبر 2026  
**المرجع:** [الخطة الرئيسية](../new/00_MASTER_PLAN.md) وتفاصيلها داخل `new/details` و`new/modules` و`new/contracts`.

هذه قائمة أعمال مستقبلية وليست قائمة إنجازات. كل بند غير منفذ ما لم يثبت قبول تنفيذه لاحقًا. أرقام E هي المعرفات الجديدة؛ أرقام Plugin القديمة تبقى للرجوع للمصادر فقط.

## 1. قواعد تحويل القائمة إلى تذاكر

كل مهمة مثل `E05.3` يمكن تحويلها إلى تذكرة ثم تقسيمها إلى Stories أصغر مع بقاء المعرف الأب. التذكرة تحتوي: المشكلة، النطاق، الدور المستخدم، التبعيات، عقد API/حدث/بيانات، صلاحيات Tenant/Branch، سلوك offline، المسار الطبيعي والفشل، معايير القبول، دليل التحقق، صاحب التنفيذ والمراجع، والإصدار المستهدف.

الأولوية **P0** تمنع الأساس أوالإطلاق، **P1** مطلوبة للإصدار المحدد، **P2** توسع لاحق. لا تخلط بينها وبين مراحل Phase 0–10 و5A/5B في الخطة الرئيسية. نستخدم أدناه كلمة «حرجة/أساسية/توسع» لتجنب الالتباس.

الحجم النسبي: **M** نحو1–2 أسبوع هندسي صافٍ، **L** نحو3–5، **XL** نحو6–10. هذه تقديرات أولية لكل Epic قبل تفكيكه، وليست مدة تقويمية ولا تشمل كل انتظار المزودين والتجارب؛ لا تُجمع مباشرة لاشتقاق جدول الخطة. البنود الممتدة على أكثر من إصدار تُقدّر لكل شريحة عند التخطيط.

## 2. E00 — تدقيق الأساس والقرارات

**الهدف:** معرفة ما نملكه وما يحتاج تعديلًا قبل توسيع المشروع. **المخرج:** G0.

- **E00.1:** تشغيل نسخة تطوير معتمدة من `composer.lock` وتثبيت PHP/extensions/DB/Node بإصدارات فعلية؛ توثيق الفرق عن AGENTS. أي تغيير dependency له قرار منفصل.
- **E00.2:** جرد Models/Migrations/Services/Observers/Events/Policies/Tests لكل مجال ERP مستخدم، وأماكن raw SQL وstatic state وconfig globals.
- **E00.3:** تشغيل الاختبارات القائمة وتسجيل الفشل السابق كما هو؛ وضع baseline للأداء والحمل على عتاد الفرع المستهدف.
- **E00.4:** استكمال ADR-01..08 ذات الأثر المبكر، خاصة Tenant/Company/Branch وruntime والمال وبلد الإطلاق.
- **E00.5:** اختيار Retail Pilot وRestaurant Takeaway Pilot منفصلين وتدفقاتهما وأصنافهـما وضرائبه ووردياته وطابعاته؛ تحديد الفريق والسعة ومعايير العرض الأسبوعي.

**القبول:** يستطيع مطور ثانٍ تشغيل baseline بنفس الخطوات؛ خريطة reuse/extend/new موثقة بالدليل؛ لا قرار blocker بلا مالك وموعد.

## 3. E01 — عزل Tenant داخل ERP

- **E01.1:** تصنيف كل جدول/setting/file/queue بين Central وTenant وEdge، وإثبات توافق إصدار Stancl المستهدف مع MySQL.
- **E01.2:** Tenant resolver موثوق للـdomain/session/device، مع default-deny عند غياب السياق للعمليات tenant-bound.
- **E01.3:** ربط Company وBranch وصلاحيات المستخدم داخل Tenant، ومراجعة `CompanyScope` ومسارات bypass/console/null-company.
- **E01.4:** تهيئة/تنظيف Tenant لكل Request/Job/Command/Webhook وعمليات الجدولة والتصدير والبث.
- **E01.5:** عزل cache/sessions/files/exports/search/permission cache/Filament settings/branding؛ اختبار مستخدم بصلاحيات مختلفة بعد آخر على نفس worker.
- **E01.6:** migrations/seed/backup/restore لكل Tenant، وتجربة نقل بيانات ERP إلى أول Tenant على نسخة غير إنتاجية.

**القبول:** محاولات HTTP وqueue وfile URL وbroadcast وexport عابرة للعملاء تفشل؛ لا تظهر هوية بصرية لعميل في آخر؛ استعادة Tenant لا تغير بيانات الآخر.

## 4. E02 — إدارة المنصة والفروع والفوترة

- **E02.1:** دورة Tenant provisioning قابلة للاستكمال، مع owner ودومينات وحالة تجهيز واضحة.
- **E02.2:** Branch قبل Edge: company/timezone/business cutoff/currency/warehouses وساعات العمل وقنوات الطلب.
- **E02.3:** حدود الفروع والأجهزة والميزات، ومصفوفة باقات واستحقاقات بإصدارات وتواريخ سريان.
- **E02.4:** لوحة تشغيل للمنصة وللعميل والفروع، مع فصل صلاحيات support والتدقيق.
- **E02.5 — R2:** checkout اشتراك ومصدر فوترة واحد، تجديد ودفع فاشل وإلغاء وupgrade/downgrade وcredits وwebhooks idempotent.
- **E02.6 — R2:** self-service لإنشاء عميل وتفعيل إضافة، رسائل حالة مفهومة، ومقاييس MRR/churn بتعريف واضح.

**القبول:** إنشاء الفرع لا يشغّل migrations جهاز لم يُربط؛ webhook مكرر لا يضاعف الاستحقاق؛ فاتورة اشتراك لا تدخل إيرادات مطعم العميل.

## 5. E03 — محرك البلجنز

- **E03.1:** refactor نقاط التحميل في Package/ServiceProvider لفصل توزيع الكود عن صلاحية التشغيل، مع الحفاظ على توافق وحدات ERP.
- **E03.2:** manifest schema بـplugin_key وvertical وscope وprice_model وrequired/optional dependencies، versions، dependencies، config schema، permissions، events، cloud/edge capability، وسياسة uninstall/retention.
- **E03.3:** dependency resolver مع كشف دورة وتعارض إصدارات؛ عرض التبعيات المدفوعة والسعر الكامل قبل الموافقة، ثم الاستحقاق والتثبيت؛ لا تثبيت خفي لإضافة غير مستحقة.
- **E03.4:** runtime guards لكل action/API/job؛ حالات requested/downloading/installed/migrated/healthy/enabled/failed.
- **E03.5:** signing pipeline للحزم وverification keys، package registry وإصدارات ثابتة وchecksums.
- **E03.6:** تجربة downgrade/suspend أثناء وجود عمل مفتوح، مع حفظ البيانات والتصدير دون down migration تلقائي.

**القبول:** عميل بلا KDS لا يستدعي خدماته حتى لو route موجود في Cloud؛ Edge بلا entitlement لا يحتوي حزمته أوجداولها الخاصة؛ خطأ dependency يظهر قبل التنفيذ.

## 6. E04 — هوية الجهاز والترخيص

- **E04.1:** Pairing Token محدود العمر، مخزن بصورة آمنة، scoped للفرع، single-use وحجز ذري مع معالجة lost-response.
- **E04.2:** تسجيل edge_id وdevice generation وحدود الأجهزة ومنع التعارض والتوثيق عند replacement.
- **E04.3:** إصدار Device Credential/certificate ودورانه وإلغاؤه، مع فصل owner/user credentials.
- **E04.4:** license payload الموقع والتحقق المحلي من scope/version/expiry/features/offline/min-version.
- **E04.5:** سياسات clock rollback وقرب انتهاء الترخيص وإلغاء الاشتراك وحالة degraded وطلبات الدعم.
- **E04.6:** تعريف إجراءات نقل الجهاز ومتى يسمح باستكمال pending transactions من نسخة مستعادة؛ لا كاتبين نشطين عشوائيًا.

**القبول:** رفض توكن مستخدم/منتهي/فرع آخر؛ إعادة محاولة نفس الربط لا تضاعف الأجهزة؛ ترخيص معدل أوخاص بجهاز آخر مرفوض؛ license صالح يعمل مع Cloud مغلق.

## 7. E05 — تجهيز Edge وتشغيله

- **E05.1:** شاشة Initial Setup فقط قبل pairing، تدعم Cloud Base URL كاملًا وتعرض أخطاء TLS/timeout/token بوضوح.
- **E05.2:** تنفيذ state machine كاملة من UNPAIRED إلى READY، مع checkpoints دائمة وresume.
- **E05.3:** تنزيل Edge Profile المعتمد وتجهيز Core DB، تنزيل الحزم المستحقة والتحقق منها، migrations مرتبة وسجل لكل محاولة.
- **E05.4:** snapshot scoped للفرع والمستخدمين والمنيو والـreferences ومكونات plugins المحلية، مع cursor متسق والتحقق من العدد والسلامة.
- **E05.5:** health checks لـDB/auth/license/plugins/queues/واجهات التشغيل؛ blockers منفصلة عن تحذير طابعة غير متاحة.
- **E05.6:** startup محلي أولًا، ثمCloud checks وsync؛ service manager وwatchdog وlocal assets.

**القبول:** قطع العملية في كل مرحلة ثمresume لا يكرر migration مدمرة ولا يتيح POS ناقصًا؛ restart بلا إنترنت بعد التجهيز يسمح بالدخول والبيع المشروعين.

## 8. E06 — المزامنة والأوامر

- **E06.1:** schema وعقد إصدار لكل حدث وأمر وstream، وسياسة compatibility وretention، مع حفظ IDs كـstrings في العقود المناسبة.
- **E06.2:** transactional Outbox فيEdge وInbox فيCloud، unique event/source IDs، durable ACK وإعادة محاولة.
- **E06.3:** cursor/aggregate version/gap handling، bounded batches، retry+jitter، dead-letter وإعادة تشغيل مدققة.
- **E06.4:** snapshot chunks وحفظ resume position وdeltas بعدsnapshot؛ إعادة تأسيس reference data دون حذف pending operations.
- **E06.5:** sync policies مستقلة لكل فرع/stream، مع last attempt/last applied/error/desired version.
- **E06.6:** persistent command queue والحالات الواردة فيinfo، وpolling fallback وexpiry وdedup ونتيجة قابلة للاستعلام.
- **E06.7:** local realtime بعدcommit وإعادة تحميل عندreconnect؛ rooms وصلاحيات scoped.
- **E06.8:** لوحة sync lag وتعارضات ERP وبيانات ناقصة ونسخ غير مطبقة؛ تدفق دعم للإصلاح دون تعديل مباشر خفي للأرصدة.

**القبول:** فقدACK وتكرار وتبديل ترتيب وقطع الشبكة أثناءsnapshot لا يفقد حدثًا مقبولًا ولا يكرر أثرًا؛ poison event لا يوقف بقية العملاء؛ إشعارpush ضائع يُعوض بالجدول.

## 9. E07 — المستخدمون والصلاحيات المحلية

- **E07.1:** نطاق branch users/roles/permissions/security policy فيCloud، مع نسخ versions مستقلة.
- **E07.2:** تخزين بيانات اعتماد محلية آمنة، session وPIN/بطاقة وفق سياسة، rate limit/lockout/logout/fast switch.
- **E07.3:** RBAC للخصم وتغيير السعر والـVoid/Refund ونقل الطاولة وفتح الدرج والطباعة والتقارير والمخزون.
- **E07.4:** manager approval مرتبط بالعملية والحدود والسبب ولا يورث صلاحيات دائمة.
- **E07.5:** تطبيق deltas للمستخدمين وتحديث الجلسات عند التعطيل حسب السياسة، مع last applied versions.
- **E07.6:** security audit يربط actor/approver/terminal/branch/operation/previous/new من دون أسرار.

**القبول:** لا حاجة إلىCloud عندlogin مشروع offline؛ المستخدم غير المسموح بالفرع مرفوض؛ API يرفض ما تخفيه الواجهة؛ تعطيل وصل وطُبق يمنع الجلسة وفق السياسة.

## 10. E08 — الأصناف والمنيو والأسعار

- **E08.1:** mapping بين product/variant/UOM الحالي وmenu item/size/category؛ أنواع خام وخدمة ومباع ووصفة وكومبو دون نسخ مصادر المنتج.
- **E08.2:** صور وترجمة وترتيب وبحث وباركود وتوفر حسب الفرع وساعات وقنوات.
- **E08.3:** modifiers بمجموعات min/max/required/free allowance، nested choices وحد عمق ومنع الدوران؛ ربط اختياري بأثر وصفة.
- **E08.4:** أسعار branch/channel/time version، ضرائب وخدمة وrounding، نشر وeffective_at، وعدم تغيير طلب قديم تلقائيًا.
- **E08.5:** snapshot payload للـEdge وواجهة إدارة Filament، واستيراد مجمع متحقق منه مع أخطاء على مستوى الصف.

**القبول:** البيع يعمل بلا PROMO/BOM؛ تغيير سعر منشور يظهر بعد applied ACK ويستخدمه الطلب الجديد؛ combo يحتفظ باختياراته الفعلية؛ تعديلpayload بالواجهة لا يغير السعر المعتمد.

## 11. E09 — POS والطلبات والحساب

- **E09.1:** استخدام E29 للحساب والدفع المشتركين مع تدفق طلب للمطعم، مع فصل حالات التحضير والدفع والتسليم والضريبة، وربط مناسب بدورة ERP.
- **E09.2:** شاشة عربية/إنجليزية للمس والاختصارات والبحث والصور والسلة والمعدلات والملاحظات، مع الصالة والسفري وتعليق الطلب واستدعائه.
- **E09.3:** استخدام E29 لحساب السعر على Edge، وحفظ نسخة الأسعار والضرائب والعروض والوصفة؛ دقة وتقريب موحدان.
- **E09.4:** تحصيل نقدي ومبلغ مستلم وباقي، وبنية split tender، ومفتاح idempotency وأقفال تمنع الدفع المتزامن الزائد.
- **E09.5:** تقسيم بمبلغ أو بالتساوي أو حسب الصنف أو المقعد؛ توزيع يحفظ مجموع الضريبة والخصم والإجمالي.
- **E09.6:** Void بسبب وصلاحية، وRefund جزئي وكلي مرتبط بالأصل والمرتجعات السابقة والوردية الحالية.
- **E09.7:** حفظ الطلب والتحصيل وOutbox وطلب الطباعة بحدود اتساق واضحة؛ فشل الطابعة لا يلغي بيعًا محفوظًا.
- **E09.8:** تدقيق ومراجعة طلبات وحالة pending sync، ومنع تكرار submit بعد تعليق الواجهة.

**القبول:** يدعم دفع السفري قبل التحضير، ودفع الصالة بعد تقديم الطعام؛ ضغط checkout مرتين لا ينتج بيعتين؛ المرتجع الزائد مرفوض؛ مجموع التقسيم يساوي الأصل.

## 12. E10 — ربط ERP ومنع ازدواج الأثر

- **E10.1:** تحديد نقاط الربط في MoveWorkflow وPaymentRegistrar وخدمات المخزون، ومراجعة الآثار التلقائية للمستمعين.
- **E10.2:** mapping وهوية مصدر فريدة وحالة import لكل طلب ودفع ومرتجع وحركة مخزون.
- **E10.3:** ربط الحسابات واليوميات والضرائب ووسائل الدفع ومراكز التكلفة والشركة والفرع؛ منع التشغيل بإعداد مالي ناقص.
- **E10.4:** Adapter للبيع والمرتجع والتسوية، يحفظ توازن القيد ويربط الأصل ويعيد نتيجة العملية عند retry.
- **E10.5:** Adapter للمخزون، مع قواعد معلنة للاستهلاك والعكس والهالك.
- **E10.6:** تقرير مطابقة بين Edge وERP يميز posted/pending/rejected، مع سبب وإجراء استكمال مدقق.

**القبول:** إعادة حدث البيع عشر مرات تنتج قيدًا واحدًا واستهلاكًا واحدًا؛ إغلاق الوردية لا يعيد إثبات الإيراد؛ فشل الاستيراد ظاهر وقابل للاستكمال.

## 13. E11 — الورديات والخزائن

- **E11.1:** أجهزة وأدراج وكاشير وورديات، مع منع التداخل غير المسموح وتحديد يوم العمل وتسليم الموظفين.
- **E11.2:** عهدة افتتاح وحركات توريد وصرف وSafe Drops وسندات وموافقات مدير.
- **E11.3:** معادلة النقدية المتوقعة، وفصل البطاقات والإكراميات والمحفظة والوسيط؛ فئات نقدية قابلة للإعداد.
- **E11.4:** X حي، ثم إغلاق أعمى وZ ثابت وموافقة فروق؛ لا تسريب expected cash عبر API.
- **E11.5:** خزنة رئيسية وعهد وتوريد بنك بحالات pending/confirmed، وربط القيود والمرفقات.
- **E11.6:** رد طلب قديم في الوردية الحالية، وإعادة طباعة Z دون إعادة حساب أو ترحيل.

**القبول:** عهدة 100 + صافي بيع نقدي 200 − Safe Drop قدره 50 = نقدية متوقعة 250؛ لا تُضاف العهدة مرتين. لا يستطيع الكاشير استخراج المتوقع قبل العد، ولا ينشأ قيد جديد بإعادة Z.

## 14. E12 — الأجهزة والطباعة

- **E12.1:** طابعة Network ونظام Edge محددان، وسجل أجهزة وتوجيه حسب المحطة ونوع المستند، وطباعة اختبار وفحص حالة.
- **E12.2:** طابور دائم وترتيب لكل طابعة وحالات sent/unknown/failed، وسياسة retry والتحويل إلى بديل.
- **E12.3:** قوالب إيصال ومطبخ وX/Z وسندات وملصقات حسب الإصدار، مع نسخة بيانات وقالب لكل مهمة.
- **E12.4:** اختبار العربية والتشكيل والأرقام والشعار وQR والقص وعرض الورق والفواتير الطويلة؛ اختيار raster أوencoding بالدليل.
- **E12.5:** فتح درج مدقق وفق وسيلة الدفع والصلاحية؛ قارئ باركود لا يمنح صلاحيات.
- **E12.6 — لاحقًا:** USB وSerial وميزان وشاشة عميل وRFID وBump Bar، مع مصفوفة الموديل والـfirmware ونظام التشغيل ونتيجة القبول.

**القبول:** restart يستعيد الطابور؛ نفاد الورق لا يفقد الفاتورة؛ unknown لا يدعي خروج ورقة مؤكدًا؛ إعادة الطباعة موسومة؛ الدعم المعلن يقتصر على العتاد المختبر.

## 15. E13 — الصالة والطاولات والحجوزات

- **E13.1:** طوابق ومخطط وطاولات ومقاعد ومناطق، مع حالة جلسة دائمة في DB وإصدار.
- **E13.2:** استقبال ضيوف وتعيين ويتر ونقل ودمج، والتحقق من صلاحيات الفرع.
- **E13.3:** نقل أصناف ومقاعد مع حفظ الدفعات وتوزيعات الخصم وإبلاغ KDS بتغير الموقع.
- **E13.4:** Hold/Fire قابل لإعادة المحاولة، وتقسيم عبر E09، وحالات served/departed/cleaned منفصلة عن paid.
- **E13.5 — R2:** حجوزات وسعة وتعارضات وانتظار وعربون وتذكير وno-show وفق سياسة، مع QR locator ثابت.

**القبول:** نادلان يفتحان نفس الطاولة ينتجان جلسة واحدة؛ النقل لا يكرر تذكرة المطبخ؛ دمج شيكين مدفوعين جزئيًا يحفظ المبالغ؛ الدفع لا يحرر الطاولة قبل نهاية جلسة الضيوف.

## 16. E14 — المطبخ ومحطات التحضير

- **E14.1:** توجيه متعدد المحطات، وربط الأصناف والمعدلات والشاشات وExpo والطابعة البديلة.
- **E14.2:** دورة حياة التذكرة والصنف، وصلاحيات الانتقال بين held/fired/preparing/ready/served، وسجل التوقيت.
- **E14.3:** واجهة KDS لمسية بالعربية والإنجليزية، ومؤقتات وألوان وملخص كميات وصوت وفق قيود المتصفح.
- **E14.4:** bump/recall/cancel وإضافات لطلب مرسل سابقًا، مع version وdedup واستعادة عند reconnect.
- **E14.5 — R3:** auto-pacing وفق أوقات تحضير قابلة للتعديل وتدخل الشيف، ودعم Bump Bar ولوحة جاهزية للعميل.

**القبول:** الصنف يصل لمحطاته فقط؛ Fire مكرر لا يعيد التحضير؛ جاهزية آخر محطة لا تعني التسليم تلقائيًا؛ انقطاع realtime لا يمحو التذاكر.

## 17. E15 — المخزون والوصفات والتكلفة

- **E15.1 — R1:** ربط منتجات ووحدات ومخازن ERP، ودفتر حركات افتتاح وبيع ورد وهالك بملكية فرع واضحة.
- **E15.2 — R1:** وصفات أساسية بأحجام ووحدات وتعبئة وإصدار تكلفة، واستهلاك مرة واحدة في الحدث المعتمد.
- **E15.3 — R2:** وصفات متداخلة وعائد وانكماش ومعدلات، ومنع الدورات؛ خامات التحضير المخزن تُستهلك عند إنتاجه فقط.
- **E15.4 — R2:** دفعات وصلاحية وFEFO وعزل وملصقات، مع فصل اختيار الدفعة عن تقييم التكلفة.
- **E15.5 — R2:** جرد أعمى بحد زمني وموافقات وفروق، وتحويل in-transit واستلام جزئي وإعادة طلب.
- **E15.6 — R2:** استهلاك نظري مقابل فعلي، وهالك بسبب ودليل واعتماد، وتاريخ تكلفة وسياسة مخزون سالب.

**القبول:** البيع وإعادته ومزامنته لا تكرر الخصم؛ الصوص المصنع لا تُخصم خاماته مرة أخرى عند البيع؛ فرق الجرد لا يمحو حركة لاحقة؛ الطلب القديم يحتفظ بتكلفته الموثقة.

## 18. E16 — العروض والكوبونات

- **E16.1:** أنواع الوقت والكمية والقيمة والمناسبة والمجموعة والحجم والفرع والقناة والولاء وBuy X Get Y.
- **E16.2:** قواعد حسم ثابتة للأولوية والأفضلية والجمع والسقف، وأوقات تعبر منتصف الليل.
- **E16.3:** quote/recalculate/commit مع إصدار وتسجيل استخدام مرتبط بالمعاملة؛ لا API عام لتسجيل أثر خصم اعتباطي.
- **E16.4:** حدود كوبون وحجز استخدام عبر الفروع أو صرف online فقط، وسياسة إلغاء ومرتجع وأهلية.
- **E16.5:** شارات وسعر قبل وبعد في POS/QR، وتقارير الاستخدام والخصم والهامش.

**القبول:** نفس السلة والنسخة والوقت تنتج نفس النتيجة؛ Buy X Get Y يحسب التكرار والأهلية والصنف المجاني؛ فرعان منقطعان لا يصرفان آخر قسيمة عالمية من رصيد cached.

## 19. E17 — المشتريات والاستلام

- **E17.1:** إعادة استخدام الموردين وPO وGRN وفواتير المورد، مع طلب شراء وموافقات وحدود ومراكز تكلفة.
- **E17.2:** استلام جزئي ومقبول ومرفوض وجودة وحرارة ودفعات وصلاحية؛ المخزون يزيد بالمقبول فقط.
- **E17.3:** مطابقة تراكمية بين PO وGRN والفواتير والمرتجعات وcredits، وحدود سماح واستثناء مصرح.
- **E17.4:** aging ومدفوعات ومطالبات ومردودات ومرفقات PDF وتاريخ أسعار ومقارنة موردين.
- **E17.5:** استلام محلي واعتماد مركزي وفق السياسة؛ الخدمات المحلية لا تحتاج فتح Filament في Cloud أثناء الانقطاع.

**القبول:** فاتورتان لا تحتسبان الكمية المستلمة نفسها مرتين؛ الزيادة تحتاج استثناء معتمدًا؛ فاتورة المورد لا تسجل GRN كزيادة مخزون ثانية.

## 20. E18 — المنيو والطلب والدفع الذاتي

- **E18.1:** منيو mobile عربي/إنجليزي بصور وبحث وأحجام وملاحظات وعروض، مع caching للأصول وسياسة حداثة الأسعار.
- **E18.2:** QR ثابت يحدد الطاولة، وجلسة قصيرة العمر تحمي العمليات؛ فصل guest APIs عن staff APIs.
- **E18.3:** cart quote ثم إنشاء أمر دائم ثم Edge ACK، مع pending/rejected/expired ورسالة قبول صحيحة.
- **E18.4:** استدعاء ويتر ومتابعة طلب، وتقسيم ودفع وإكرامية عبر E20؛ منع كشف شيك بلا جلسة مصرح بها.
- **E18.5:** تجربة Wi-Fi الضيوف وmobile data وHTTPS وانقطاع Edge أوCloud، وتحديد المتاح لكل حالة.

**القبول:** الطلب غير المقبول من Edge لا يظهر accepted؛ تبديل table_id لا يكشف طاولة أخرى؛ تغيير السعر أو نفاد الصنف يحتاج نتيجة واضحة؛ رفض طلب سبق دفعه له تعويض موثق.

## 21. E19 — التكامل الضريبي

- **E19.1:** تحديد الدولة ونوع المنشأة وB2B/B2C والمتطلبات الرسمية الحالية مع خبير المجال.
- **E19.2:** Adapter مستقل لكل منظومة، وإعداد شهادات وهوية أجهزة وأكواد أصناف وحماية مفاتيح.
- **E19.3:** نسخة مستند وتسلسل وتوقيع وإرسال واستعلام حسب العقد الرسمي، منفصل عن معرف الطلب الداخلي.
- **E19.4:** طابور انقطاع ومحاولات ورفض وتصحيح وإشعارات دائنة، وربط عدة مستندات بالطلب عند الحاجة.
- **E19.5:** قبول sandbox واعتماد متطلبات الإنتاج وطباعة الحقول اللازمة وتجديد الشهادة.

**القبول:** نجاح سيناريوهات البلد المطلوبة؛ المستند المصدر لا يعدل بأثر رجعي؛ الرفض ظاهر؛ لا إطلاق تجاري قبل بوابة الامتثال اللازمة.

## 22. E20 — المدفوعات والأجهزة المصرفية

- **E20.1:** مزود أول متاح بعقد وsandbox، ومصفوفة قدرات؛ لا وعد بخدمة تحويل أوتقسيط دون API مؤكد.
- **E20.2:** محاولة دفع وحالة ومفتاح idempotency ومبلغ وعملة ومرجع وحجز allocation، وربط الجهاز بالفرع.
- **E20.3:** initiate/inquiry/approve/decline/cancel/unknown، والتحقق من توقيع callback ومنع replay.
- **E20.4:** رد جزئي بصلاحية ومبلغ قابل للرد؛ معالجة callback متأخر بعد دفع نقدي وتحصيل زائد.
- **E20.5:** رسوم وتسويات واعتراضات حسب المزود، ومطابقة حساب وسيط في ERP.

**القبول:** timeout لا يسبب خصمًا ثانيًا تلقائيًا؛ webhook مكرر لا يضاعف التحصيل؛ اختلاف المبلغ أوالعملة أوالمصدر مرفوض؛ البيع المحلي لا يعد بتحصيل بطاقة دون اتصال.

## 23. E21 — التوصيل والقنوات الخارجية

- **E21.1:** سائقون ومناطق ورسوم وعناوين ومهام وحالات تعيين واستلام وتسليم وفشل.
- **E21.2:** تسليم نقدية السائق للخزنة وفروق وعمولات ومراجع تسليم.
- **E21.3:** Adapter لمجمع واحد أولًا؛ webhook وهوية طلب خارجية وmapping للأصناف والمعدلات والمنيو والتوفر.
- **E21.4:** قبول أو رفض أو انتهاء انتظار يعتمد Edge ACK؛ الصنف غير المعروف يذهب للمراجعة.
- **E21.5:** retries وإلغاء متزامن وحالات متأخرة ودفع خارجي وعمولة وتسوية مستقلة.

**القبول:** الطلب الخارجي لا ينشأ مرتين؛ تعيين السائق لا يعني خروجه للتوصيل؛ فرع منقطع لا يؤكد قبولًا غير حقيقي؛ التسوية تطابق الإجمالي والرسوم والصافي.

## 24. E22 — CRM والولاء والمحفظة والحملات

- **E22.1 — R2:** ربط العميل بـpartner، وبحث وتسجيل سريع وعناوين وتفضيلات وموافقات اتصال ومنع تكرار ودمج مدقق.
- **E22.2 — R3:** دفتر نقاط وفئات واكتساب وصرف وانتهاء وبونص وتعديل ومرتجع مرتبط بالبيع.
- **E22.3 — R3:** دفتر محفظة وشحن ودفع ورد ورصيد متجر، وربط التزام العميل بالحسابات.
- **E22.4 — R3:** منع الصرف المزدوج عبر فروع offline بسلطة مركزية أو حصص محجوزة محدودة.
- **E22.5 — R3:** RFM وحملات عيد ميلاد واستعادة عملاء وSMS/WhatsApp، مع موافقة وقالب وسقف إرسال وإلغاء اشتراك وسجل تسليم.

**القبول:** نقاط pending لا تصبح قابلة للصرف عالميًا؛ شحن المحفظة لا يسجل كإيراد وجبات؛ المرتجع يعكس النقاط حسب السياسة؛ دمج العميل لا يكرر الرصيد.

## 25. E23 — المطبخ المركزي والتصنيع

- **E23.1:** استخدام BOM وأوامر ومراكز عمل ERP، مع احتياجات فروع واعتماد وتجميع.
- **E23.2:** تخطيط إنتاج وسعة وجدولة وكميات مخططة وفعلية وعائد وهالك وناتج جانبي.
- **E23.3:** تتبع من الخام إلى دفعة الإنتاج والتعبئة والتحويل والاستلام، مع ملصق وصلاحية وQC.
- **E23.4:** نقل in-transit واستلام جزئي ورفض وسلسلة تبريد وعزل وتسوية فرق.
- **E23.5:** ربط تكلفة الإنتاج والتحويل بالحسابات الحالية.

**القبول:** يمكن تتبع مصدر كل دفعة ومواقعها؛ استهلاك وإنتاج مرة واحدة؛ الفرع لا يزيد رصيده قبل الاستلام؛ فرق الوزن له قرار وتسوية.

## 26. E24 — HQ والفرانشايز

- **E24.1:** مناطق ومجموعات وملكية وعقود ودور مركزي ومحلي ضمن حدود Tenant.
- **E24.2:** نشر منيو وأسعار ووصفات مع قفل أوprice band أوتخصيص محلي، وإصدارات وACK لكل فرع.
- **E24.3:** رسوم امتياز وتسويق ومبلغ ثابت بتعريف وعاء المبيعات والاستبعادات والعملة والفترة في العقد.
- **E24.4:** فواتير دورية مرتبطة بـERP، وتعديلات فترات متأخرة واعتراضات وتسويات.
- **E24.5:** تقارير مجمعة مع حداثة البيانات، ومقارنة فروع متماثلة، وقواعد معتمدة لتجميع الشركات والعملات.

**القبول:** الفرع المنقطع يبقى pending؛ تغير الأسعار لا يعدل إيصالًا قديمًا؛ إعادة حساب نفس الفترة لا تفوتر مرتين؛ البيانات المتأخرة لا تمحو فترة مقفلة.

## 27. E25 — التقارير والذكاء التجاري

- **E25.1 — R1:** مبيعات حسب الوردية والقناة والصنف والضريبة، وتحصيل ومرتجعات وخصومات ونقدية وفروق ومطابقة ERP.
- **E25.2 — R1:** حداثة وتقارير pending/rejected imports، وتصدير مقيد بالعميل والفرع والصلاحيات.
- **E25.3 — R2/R3:** تكلفة وهامش وهالك وجرد وaging ومبيعات فروع وسرعة خدمة وتكلفة عمالة عند توفر بياناتها.
- **E25.4 — R3:** مصفوفة منيو بتعريف واضح للشعبية وهامش المساهمة والفترة ونسخة البيانات.
- **E25.5 — R4:** توقع مقابل baseline موسمي، وbacktesting ومقاييس WAPE/MAE المناسبة وفترات ثقة ومراقبة تغير البيانات.
- **E25.6 — R4:** توصيات أسعار وعروض ومشتريات تعتمد بشريًا؛ تنبيه الانحراف يحتاج تحقيقًا ولا يثبت سرقة.

**القبول:** التقرير يرجع لمستنداته؛ الفرع المنقطع ظاهر؛ لا ضمان 85% قبل بيانات وتجربة؛ AI سحابي فقط ولا يملك صلاحية كتابة سعر أوطلب شراء أوحركة مخزون؛ قبول التوصية لا ينفذها تلقائيًا، والتنفيذ اليدوي في ERP منفصل.

## 28. E26 — النشر والتحديث والاستعادة والتشغيل

- **E26.1:** Pipeline لإصدارات Cloud وEdge والبلجنز، وحزم مقفلة وموقعة ومتوافقة وسجل إصدارات.
- **E26.2:** Installer وخدمات DB/runtime/workers/watchdog وأصول محلية وشهادة LAN وجدار حماية وسجلات.
- **E26.3:** تحديث مرحلي بالتنزيل والتحقق والنسخ وdrain وmigrations وhealth وACK، مع canary وحد توقف.
- **E26.4:** نسخ Central/Tenant/Edge/files/keys، واستعادة على spare مع حفظ Outbox وجيل الجهاز.
- **E26.5:** مراقبة القرص والطوابير والمزامنة والدفع المجهول والترخيص والنسخ؛ إجراءات دعم وصلاحيات ومسؤولون.
- **E26.6:** تأمين الشبكة والأسرار والتحديثات، وسياسات احتفاظ وتدوير سجلات وتشخيص لا يكشف بيانات حساسة.

**القبول:** رجوع متوافق مع schema أوrestore مثبت؛ الخدمة تعود بعد restart؛ النسخة صالحة بالتجربة؛ الاتصال المحلي المصرح يستمر عند انقطاع الإنترنت.

## 29. E27 — الترحيل والـPilot والإطلاق

- **E27.1:** فرع ومستخدمون ومسؤول قرار، وUAT لليوم التشغيلي من الافتتاح إلى الإغلاق والاستعادة.
- **E27.2:** mapping للبيانات الحالية والقديمة والمعرفات والوحدات والضرائب والأرصدة؛ تجارب وتقارير رفض ومطابقة مالية.

**القبول:** لا خطأ مالي أوعزل أوفقد بيانات حرج؛ الأرصدة مطابقة؛ التدريب والدعم وملكية التشغيل واضحة؛ محاضر القبول أساس الإطلاق.

## 32. متابعة تقدم الفريق

الحالات: Not Started → Ready → In Progress → In Review → In Acceptance → Done. حالة Blocked لها سبب ومسؤول إزالة العائق وموعد مراجعة. تُحسب النسبة من Stories المقبولة، لا عدد الملفات والجداول.

أول دفعة: E00.1–E00.5، ثم E01.1/E01.2/E02.2 وعقود E04/E06/E09/E10. الواجهات المتقدمة والحملات والـAI لا تسبق إثبات G3. يراجع الفريق نطاق الإصدار ومعايير قبوله قبل سحب عمل من المراحل اللاحقة.


## 33. E29 — Shared Sales Engine / Phase 4

- **E29.1:** استخراج عقود السلة والإجماليات والضريبة والخصم والدفع والمرتجع كخدمات مشتركة؛ E09 يحتفظ بتدفقات المطعم.
- **E29.2:** حالات حساب مرجعية مشتركة مع ERP، ودقة Decimal وتوزيع التقريب دون ازدواج تطبيق.
- **E29.3:** snapshots ومعرّفات مصدر عالمية وحدود Transaction/Outbox وidempotency.
- **E29.4:** المحرك لا يفترض table أوkitchen أوrecipe؛ adapters النشاط منفصلة.

**القبول:** نفس حالات الحساب في النشاطين تنتج نفس القيم، وإعادة الطلب لا تكرر أثر المال والمخزون. E10 المالي الأساسي شرط Pilot ولا ينتظر تكاملات Phase 7 المتقدمة.

## 34. E30 — Retail POS / Phase 5A

- **E30.1:** باركود أولًا، بحث سريع، كمية، عميل اختياري وتعليق واستدعاء سلة.
- **E30.2:** نقدي ومرتجع/استبدال بمعاملات مترابطة، باستخدام E29 وE10.
- **E30.3:** Profile RETAIL دون تنزيل أوتهيئة Tables/KDS غير المستحقة.
- **E30.4:** صلاحيات ووردية وطباعة وفق العمليات المفعلة، وrestart offline وreplay مع فقد ACK.

**القبول:** AC-13 وإيصال واستيراد صحيح، دون اعتماد على مسارات مطعم.

## 35. E31 — Waiter / Phase 6

- **E31.1:** PWA محلية لأخذ الطلب وإرساله وطلب الحساب وفق الصلاحيات.
- **E31.2:** تدفقات الطاولات تتطلب Tables عند اختيارها، دون فرضها على كل Restaurant POS.
- **E31.3:** إعادة الاتصال تستعيد الحالة من Edge ولا تنشئ مصدر معاملات في المتصفح.

**القبول:** الطلب المكرر لا يكرر الإرسال للمطبخ، ولا يتجاوز الويتر صلاحيات الخصم والتحصيل.
